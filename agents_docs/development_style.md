# 开发风格专题

本文档记录适合按需读取的项目开发偏好；稳定架构红线与强制规则仍以 `AGENTS-DEV.md` 为准。

## 当前偏好

- 运行时按职责拆分：`session.py` 保持 facade，具体能力优先下沉到对应子模块。
- 新能力优先补到既有归口，而不是在 Web、会话层或调用方旁路散落特判。
- 复杂流程优先继续拆阶段 helper 或私有状态对象，避免把主循环重新堆成巨型函数。
- 新增能力时，测试应跟着归口一起补齐，尤其关注会话、工具和 Web 边界。

## 常见反模式

- 看到 `session.py` 好找就继续往里塞实现细节。
- 为了短期方便在多个层级重复做同一类序列化、注册或状态判断。
- 只更新实现，不同步更新 `AGENTS-DEV.md` 与相关导航文档。
