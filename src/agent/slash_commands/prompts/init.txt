生成一个名为 AGENTS.md 的文件，并直接写入 `{agents_path}`，作为当前工作区中 Agent 每轮都会加载的最小入口文档。

你的目标不是生成普通贡献者指南，而是产出一份“运行时最小指令集”：只保留每轮都值得放进上下文的高优先级信息，让 Agent 能先知道该遵守什么、再去哪里读取更详细的开发资料。

---

## 文档定位

- `AGENTS.md` 只承载最小高优先级规则与文档导航
- 更完整的开发主手册应放在 `AGENTS-DEV.md`
- 面向 Agent 自主读取的专题文档应放在 `agents_docs/`
- 不要把详细架构说明、长篇规范、专题知识或一次性总结堆进 `AGENTS.md`

## 必须覆盖

### 文档优先级

- 明确 `AGENTS-DEV.md` 是后续开发主手册
- 明确 `agents_docs/` 用于按主题补充更细的开发知识
- 明确 `README.md` 与 `docs/` 的职责边界

### 必须每轮生效的高优先级规则

- 只保留少量真正需要立即约束 Agent 的规则
- 优先提炼架构红线、安全边界、关键测试要求、不可误改点
- 这些规则应短、硬、可执行，避免泛泛而谈

### 最小必要导航

- 列出关键入口、核心命令或最常用测试命令
- 如果仓库已有更详细文档，应优先指向这些文档，而不是在本文件重复展开

## 结构要求

- 文档标题可使用 "Repository Guidelines"
- 全文使用 Markdown，结构清晰
- 内容保持简洁，优先控制在 200–400 字
- 使用专业、直接、可执行的语气
- 如需举例，只保留最能帮助 Agent 立刻行动的少量示例
